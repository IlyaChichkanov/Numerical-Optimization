# Правила работы агентов

## Git и передача контекста (поручение пользователя 08.11.2026)

- После каждого крупного законченного изменения обновлять `PROJECT_CONTEXT.md` и связанные документы: цель, выполненная работа, решения и причины, изменённые файлы, проверки с результатами, ограничения и следующий шаг. Контекст должен позволять другому агенту продолжить работу после clone, без истории чата.
- Проверять `git status`, diff и состав коммита, выполнять подходящие проверки, затем делать осмысленный commit и push рабочей ветки в настроенный репозиторий GitHub. Для обычного сохранения завершённой работы повторное разрешение не требуется. При отсутствии remote настроить приватный репозиторий; не менять существующую видимость.
- В общем checkout сохранять только изменения своей задачи, указывать явные пути, не включать чужую незавершённую работу. Не делать force push, reset/clean и не перезаписывать историю. При занятом индексе или конфликте сохранить файлы и сообщить о блокировке.
- Для учебных, командных и сторонних origin сохранять исходный remote; резервирование делать в разрешённый GitHub remote `backup`, если origin не предназначен для личной резервной копии. Это не разрешает сдачу в LMS, контест, deploy или изменение оборудования.
- Перед загрузкой проверять файлы на секреты и персональные данные. Не добавлять ключи, токены, cookies, `.env`, базы, данные учеников, переписки, окружения, кэши и приватные локальные отчёты. Не обходить `.gitignore` через `git add -f`.
- Проверять успешность push по SHA удалённой ветки. При ошибке сообщать, что осталось только локально; не выдавать наличие `.git` или remote за успешную синхронизацию.
