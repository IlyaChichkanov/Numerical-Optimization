# Как сдать домашнее задание

**С ДЗ 3 у каждого студента свой закрытый репозиторий на весь курс:** `optimisation-misis-2026/numopt-<ваш логин>`. Его видите только вы и преподаватель — чужие работы не видны никому. Каждая домашка появляется в нём отдельной папкой: `hw3/`, `hw4/`, … Git знать не обязательно: всё делается на сайте github.com.

ДЗ 1–2 сдавались pull request'ом в этот репозиторий — [инструкция ниже](#дз-12-pull-request-в-репозиторий-курса). Кто уже сдал ДЗ 3 pull request'ом, ничего переделывать не нужно: работа засчитана. Новые pull request'ы с решениями больше не открывайте.

## Один раз в начале

1. **Аккаунт на GitHub.** Ваш логин уже есть в ведомости курса — тот, с которого вы сдавали ДЗ 1–2. Сменили аккаунт или не сдавали ни одной работы — напишите преподавателю логин: это имя после `github.com/` в адресе вашей страницы, его же видно, если нажать на аватар в правом верхнем углу github.com.
2. **Примите приглашение.** На почту, привязанную к GitHub, придёт письмо о приглашении в репозиторий `numopt-<ваш логин>` организации `optimisation-misis-2026`. Нажмите в нём **View invitation → Accept invitation**. Письма нет — откройте [github.com/notifications](https://github.com/notifications) или страницу `https://github.com/optimisation-misis-2026/numopt-<ваш логин>/invitations`. Приглашение одно на весь курс.

## На каждое задание

### 1. Найдите задание

Когда преподаватель выдаёт задание, в вашем репозитории появляется папка `hwN/` (N — номер ДЗ):

* `hwN/homework.ipynb` — задание (тот же ноутбук, что `homeworks/hwNN.ipynb` в репозитории курса);
* `hwN/README.md` — сроки, баллы и состав задания;
* `hwN/quiz/` — пока не трогайте: квизы появятся позже.

Папки прошлых заданий остаются на месте, их не трогайте.

### 2. Решите задание

* Скачайте `hwN/homework.ipynb` (на странице файла кнопка **⋯ → Download**) и откройте в Jupyter или в [Google Colab](https://colab.research.google.com) (*Файл → Загрузить блокнот*). Локально удобнее всего из клона этого репозитория: `uv sync`, затем `uv run jupyter lab` (см. [README](README.md#быстрый-старт)).
* Код пишите в ячейках-заготовках, текстовые ответы и выкладки — в markdown-ячейках вместо заготовки ответа (формулы — в $\LaTeX$). Выкладки «на бумаге» можно сфотографировать или сохранить в PDF и положить в ту же папку `hwN/`.
* **Перед сдачей выполните ноутбук целиком:** в Jupyter — *Kernel → Restart Kernel and Run All Cells*, в Colab — *Среда выполнения → Перезапустить сеанс и выполнить все*. Сохраните файл; из Colab — *Файл → Скачать → Скачать .ipynb*.

### 3. Загрузите работу

1. Откройте свой репозиторий на github.com и **зайдите в папку задания `hwN/`**.
2. Нажмите *Add file → Upload files*, перетащите решённый `homework.ipynb` (имя файла не меняйте) и, если есть, фото или PDF; внизу нажмите **Commit changes**. Старый файл заменится новым. Если загрузить из корня репозитория, файл ляжет не туда.

Умеете работать с git — можно через `git clone` / `git push`, результат тот же.

### 4. Посмотрите на автопроверку

Через минуту-две после загрузки рядом с последним изменением появится значок:

* ✅ — ноутбук на месте, выполнен целиком, упавших ячеек и незаполненных заготовок нет;
* ❌ — что-то не так: нажмите на крестик → *Details*, внизу страницы будет список, что поправить.

Галочка значит «работа в порядке по форме», а не «решено верно»: решения, выкладки и текстовые ответы проверяются после дедлайна, отзыв придёт отдельно.

### Частые проблемы

| Что видите | Что делать |
|---|---|
| «не выполнено ячеек с кодом», «ноутбук не запускался» | Файл сохранён без выводов или выполнен не весь. Выполните все ячейки заново и загрузите ещё раз. |
| «ячейки с кодом, упавшие с ошибкой» | В перечисленных ячейках ошибка (номер — порядковый номер ячейки с кодом сверху). |
| «остались незаполненные заготовки» | В перечисленных ячейках остались `raise NotImplementedError`, `# TODO` или `x = ...`. |
| «файла нет» про `hwN/homework.ipynb` | Ноутбук загружен не в ту папку или переименован. Загрузите в `hwN/` под именем `homework.ipynb`, лишнюю копию удалите. |
| Нет письма-приглашения | Проверьте [уведомления](https://github.com/notifications) и напишите преподавателю свой логин. |
| Нет папки нового задания | Задание ещё не выдано — дождитесь объявления. |

## Сроки

Исправлять и загружать заново можно сколько угодно раз до дедлайна. В зачёт идёт последняя версия, загруженная **до** дедлайна (время загрузки фиксирует GitHub). Дедлайны и баллы — в [программе курса](syllabus.md#4-домашние-задания) и в `hwN/README.md`.

Задачи можно обсуждать, но решение пишется самостоятельно. Свою работу никому не показывайте и чужие не берите.

## ДЗ 1–2: pull request в репозиторий курса

Так сдавались ДЗ 1–2 (и первые работы ДЗ 3). Сданные работы лежат в [`submissions/`](submissions/README.md); новые туда больше не принимаются.

### Один раз: форк

1. Нажмите **Fork** в правом верхнем углу [репозитория курса](https://github.com/IlyaChichkanov/Numerical-Optimization) — у вас появится собственная копия под вашим аккаунтом.
2. Склонируйте свой форк себе:

   ```bash
   git clone https://github.com/<ваш-логин>/Numerical-Optimization.git
   cd Numerical-Optimization
   git remote add upstream https://github.com/IlyaChichkanov/Numerical-Optimization.git
   ```

   `upstream` — это репозиторий курса; из него вы будете забирать новые лекции и задания, а `origin` (ваш форк) — то, куда вы пушите решения.

### На каждое задание

1. Обновите свою копию перед началом работы:

   ```bash
   git checkout main
   git fetch upstream
   git merge upstream/main
   git push origin main
   ```

2. Создайте ветку под конкретное задание — имя ветки значения не имеет, но так проще ориентироваться:

   ```bash
   git checkout -b hw01-<фамилия>
   ```

3. Скачайте условия (`homeworks/hw01.ipynb`), выполните и заполните ноутбук, перед сохранением — `Kernel → Restart Kernel and Run All Cells`.
4. Положите заполненный ноутбук в `submissions/hw01/<фамилия>.ipynb` (см. [`submissions/README.md`](submissions/README.md)) и закоммитьте:

   ```bash
   git add submissions/hw01/<фамилия>.ipynb
   git commit -m "hw01: <фамилия>"
   git push origin hw01-<фамилия>
   ```

5. На странице своего форка на GitHub нажмите **Compare & pull request**. Base repository — `IlyaChichkanov/Numerical-Optimization`, base — `main`; head — ваш форк и ветка `hw01-<фамилия>`. Название PR — `hw01: <фамилия>`.
6. Дождитесь комментария с оценкой прямо в PR. Если нужно что-то исправить — коммитьте в ту же ветку, PR обновится автоматически, повторно открывать не нужно.

Дедлайн — момент открытия PR (по времени коммита в GitHub), а не мержа: мержить будет преподаватель после проверки.

### Если раньше не пользовались git/GitHub

Ничего сложного, но лучше один раз потренироваться до первого дедлайна:

- [GitHub: Fork a repo](https://docs.github.com/en/get-started/quickstart/fork-a-repo)
- [GitHub: About pull requests](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/about-pull-requests)
- Ноутбук можно редактировать локально (`uv run jupyter lab`, см. [README](README.md#быстрый-старт)) или прямо в вашем форке через [GitHub Codespaces](https://github.com/features/codespaces) — тогда `git`-команды не нужны вовсе, коммит и push делаются кнопками в интерфейсе.
